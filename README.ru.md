# Test Designer

[English](README.md) · [Участие в проекте](CONTRIBUTING.md) · [Безопасность](SECURITY.md)

Переносимый Agent Skill для проектирования тестов **до написания тестового кода**.
Подходит для backend, web, CLI, мобильных и desktop-приложений, библиотек — без
обязательного языка, фреймворка, MCP или тестового runner.

Результат: какое поведение защитить, почему, какими данными и действиями, что
наблюдать и на каком уровне. Скилл сначала исследует требования, вызывающий код,
состояния и имеющиеся проверки, затем выбирает полезные сценарии.

## Возможности и границы

- Обнаружение тестовых инструментов, fixtures, окружений, команд и CI.
- Happy, альтернативные, unhappy и recovery пути без обязательных квот.
- Классы эквивалентности, точные границы, таблицы решений, последовательности,
  свойства и взаимодействия факторов по структуре поведения.
- Независимые ожидания, различающие данные, разрешённые и запрещённые эффекты.
- Решения KEEP / UPDATE / ADD / NO_NEW_TEST с объяснением имеющейся защиты и пробелов.

`UPDATE` означает изменение плана сценариев. Дизайнер не пишет, не исправляет и
не запускает тесты, не выдаёт ACCEPT/REVISE готовому коду и не доказывает его
стабильность. Если нужен критик, он ревьюит написанные тесты до исполнения;
исправляет автор вне роли критика. Самопроверка автора не является независимым ревью.

## Установка

Через [skills CLI](https://github.com/vercel-labs/skills):

```bash
npx skills add letya999/test-designer --skill test-designer
```

Проверить обнаружение без установки:

```bash
npx skills add letya999/test-designer --list
```

По умолчанию используется текущая ветка разработки `dev`. Для установки `main`:

```bash
npx skills add https://github.com/letya999/test-designer/tree/main --skill test-designer
```

CLI требует Node.js/npm. Для ручной установки они не нужны: скопируйте `SKILL.md`,
`LICENSE` и весь `references/` в каталог `test-designer/` в директории skills вашего
клиента, сохранив относительные пути. Архив `dist/test-designer.skill` создаётся
локальной командой упаковки. README, AGENTS, evals и authoring-скрипты в минимальный
архив не входят.

[skills.sh](https://skills.sh/docs/faq) учитывает установки через CLI: публикация
репозитория сама по себе не подтверждает появление в каталоге или место в рейтинге.

## Применение

```text
$test-designer Спроектируй проверки срока действия приглашения.
$test-designer Какие кейсы нужны для offline-сохранения и восстановления процесса?
$test-designer Изучи форму в разрешённом dev-окружении и составь тест-план.
```

Укажите изменение, проект или артефакты, активные требования и ограничения.
При исследовании UI нужен безопасный адрес и доступный инструмент. Без живого
окружения скилл проектирует по исходникам и явно обозначает непроверенное.

Точка входа — [SKILL.md](SKILL.md). [Исследование кейсов](references/case-research.md),
[техники](references/design-techniques.md), [банк качества и шаблоны](references/quality-bank.md)
и [источники](references/sources.md) доступны отдельно. Инструкции скилла английские,
ответ выдаётся на языке пользователя.

Скилл сохраняет правила AGENTS и маршруты к документации целевого проекта,
сочетается с Ponytail, Probity и Memory Bank, не устанавливает их и не обходит
обязательные инструменты или хуки. Совместимость с каждой будущей конфигурацией
не обещается.

## Разработка и проверки

Поток: **feature → dev → main**. `dev` — default; `main` защищена, принимает PR
только из `dev` этого же репозитория после обязательных проверок и разрешения
обсуждений. Защита распространяется на администраторов; force push и удаление
`main` запрещены. Для promotion используйте merge commit и сохраняйте ветку `dev`.

В изолированном Python-окружении:

```bash
python -m pip install -r requirements-dev.txt
python scripts/validate.py --package
python -m unittest discover -s scripts -p "test_*.py" -v
```

CI проверяет структуру, ссылки, языки, evals, состав пакета и authoring-скрипты;
Bandit проверяет authoring Python, Gitleaks сканирует историю. Это не запуск тестов пользовательского приложения и
не доказательство эффективности модели. Полный слепой сравнительный benchmark,
реальная интеграция MCP/native и автоматические триггеры пока не подтверждены.
